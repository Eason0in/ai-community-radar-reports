### 1. ChatGPT 強化跨內容搜尋

OpenAI 在 7 月 14 日更新 ChatGPT 搜尋功能，現在能從同一入口搜尋過往對話、Projects、圖片與上傳文件，也能依內容類型篩選。官方表示此功能已提供全球所有方案使用。

### 2. AI Agent 已被用於真實勒索攻擊

Sysdig 公布 JADEPUFFER 案例，並稱它是首個有紀錄、由 LLM Agent 執行完整技術攻擊鏈的勒索行動。Agent 利用公開 Langflow 漏洞取得初始權限，尋找憑證、橫向移動，並對資料庫執行破壞與勒索。研究紀錄中，一次失敗登入後，Agent 在 31 秒內產生可用修正。

**重要限制**

這不代表完全沒有人參與。後續查證顯示，人類仍負責選擇目標和啟動行動，只是技術執行主要由 Agent 完成。Sysdig 也無法確認實際使用的是哪一個模型。

**來源**

- [Sysdig：JADEPUFFER 原始研究](https://www.sysdig.com/blog/jadepuffer-agentic-ransomware-for-automated-database-extortion) — 第一手研究，2026-07-01
- [TechCrunch：事件仍有人類參與](https://techcrunch.com/2026/07/06/the-first-ai-run-ransomware-attack-still-needed-a-human/) — 交叉查證，2026-07-06

### 3. AI 正降低網路攻擊的技術門檻

近期報導指出，攻擊者已從使用 AI 試寫程式，進入真實攻擊執行。地下市場也開始提供解除限制的模型、攻擊服務與提示方法。

目前的 AI 攻擊仍會留下低級錯誤，例如暴露伺服器、留下明顯活動紀錄，甚至生成可能不存在的加密貨幣地址。短期內更實際的風險不是完美的全自動駭客，而是一般攻擊者能更快測試更多目標。

## 3. 新技術與新方法

### Agent 安全邊界必須成為產品功能

JADEPUFFER 顯示，Agent 的風險不只來自模型回答錯誤，而是模型取得工具、憑證和網路權限後，可以快速重試並調整策略。

實務上應將以下控制視為 Agent 產品的基本功能：

1. 工具使用最小權限。
2. 將高風險命令與一般讀取操作分開。
3. 執行外部程式或修改資料前要求人工確認。
4. 限制 Agent 可讀取的環境變數與憑證。
5. 偵測短時間大量重試、橫向存取及異常工具呼叫。
6. 保留完整、可稽核的工具使用紀錄。

## 6. 今天值得嘗試

檢查一項對外開放、由 AI Agent 使用的服務：

1. 確認套件和框架是否為最新版。
2. 檢查管理介面是否直接暴露在網路上。
3. 不要把 API Key 長期放在 Agent 可直接讀取的環境。
4. 限制 Agent 的檔案、網路和命令執行權限。
5. 為異常的大量工具呼叫或快速重試設定警示。
