### 1. Thinking Machines 發布首款開放權重模型 Inkling

Thinking Machines Lab 於 **2026-07-15** 發布 Inkling：975B 總參數、41B 啟用參數的 MoE 多模態模型，支援最長 1M token context，預訓練資料包含 45 兆個文字、圖片、音訊與影片 token。完整權重已放上 Hugging Face，也能在 Tinker 微調；Tinker 當前提供 64K／256K context 選項。同步預告的 Inkling-Small 為 276B 總參數、12B 啟用參數，但仍在測試，尚未釋出完整權重。

### 2. Bonsai 27B 把 27B 級多模態模型壓到手機容量

PrismML 於 **2026-07-14** 發布基於 Qwen3.6 27B 的 Bonsai 27B：

### 3. OpenAI 推出 Codex Micro 實體 Agent 控制器

## 3. 新技術、新方法

### Claude「Memory Heist」：唯讀瀏覽也能成為資料外洩通道

安全研究者 Ayush Paul 在 **2026-07-09** 公開一個針對 claude.ai 的實驗：惡意網站對一般瀏覽器顯示正常咖啡店頁面，卻對 `Claude-User` user-agent 顯示提示注入內容；網站以逐字母超連結建立一棵路徑樹，誘使 Claude 把姓名、公司、成長城市等記憶資訊編碼進連續 GET request URL。這繞過了「不能直接組任意 URL」的限制，因為 Claude 當時可沿著已抓取頁面上的連結繼續瀏覽。

研究者稱 Anthropic 已停用 `web_fetch` 跟隨外部頁面連結的能力，只允許抓取搜尋結果與使用者直接提供的 URL；截至本次查核，未找到 Anthropic 對這個個案的正式公告，因此修補狀態應標示為**研究者說法**。

這個案例的通用教訓不是「不要開記憶」，而是：

1. Agent 的讀取工具也可能透過 URL、DNS、圖片或錯誤訊息形成隱蔽輸出通道。
2. 記憶、郵件、Drive、MCP 等敏感來源不應自動和不受信任網頁內容放在同一個工具迴圈。
3. 每次跨 trust boundary 的資料使用，都要做來源標記、目的限制與使用者可見的批准。

- [Hacker News 討論](https://news.ycombinator.com/item?id=48916975) — 2026-07-15 再度受到高度關注

### 用小型 DSL 與 deterministic validator 約束 Coding Agent

Thoughtworks 的 Unmesh Joshi 在 **2026-07-14** 提出一個實務模式：先建立窄而明確的 domain model／DSL，再讓 LLM 只在這個受限語彙內生成，最後用 parser、JSON Schema、type checker 或 compiler 驗證並讓 Agent 自動修正。DSL 的價值不是讓提示詞更長，而是把「合法狀態空間」縮小，並把錯誤轉成可機器處理的 domain-level feedback。

適合：部署規格、測試情境、工作流、資料轉換、圖表描述。
不適合：需求仍快速變動、語言邊界尚不清楚，或維護 DSL 的成本高於錯誤成本的任務。

- [Martin Fowler：DSLs Enable Reliable Use of LLMs](https://martinfowler.com/articles/llm-and-dsls.html) — 第一手工程文章，2026-07-14

**快速摘要：** 這是一堂以 Codex 桌面版為主的 35 分鐘入門課。作者先介紹安裝、介面、模型與 plugins，再實際示範 Computer Use、Chrome 控制、建立小型 chess app、`/plan`、`/goal`、worktree、`/review`、`AGENTS.md` 與 scheduled tasks。優點是功能覆蓋完整且有成功、失敗都保留的實測；主要問題是錄製畫面的模型建議已落後於目前官方文件，因此適合學「工作流」，不適合照抄模型與方案判斷。

## 6. 今天值得嘗試

### 把一個 Agent 輸出改成「可驗證的小語言」

挑一個原本由 Agent 直接產生自由格式內容的任務，例如部署設定、資料清理規則或測試案例：

1. 先用 JSON Schema、TypeScript type 或小型 YAML 規格定義唯一合法輸出。
2. 提供 2–3 個正確範例與 1 個故意失敗範例。
3. 讓 Agent 只生成規格檔，不直接執行副作用。
4. 以 validator／compiler 驗證。
5. 把錯誤訊息交回 Agent 修一次，記錄首次通過率與修正後通過率。
6. 通過後才交給執行器，並保留人工批准。

這個 20–30 分鐘實驗可以直接驗證：你的問題是否適合以 DSL／schema 降低 Agent 幻覺與 review 成本。
