### 3) Shieldstral 把多模態內容審核改寫成可配置的 yes／no 問題

- **論文日期：2026-07-28；預印本**
- Shieldstral 是基於 Ministral-3B 的 3B 參數多模態 safety classifier。輸入包含使用情境、自然語言政策問題與待檢內容，模型只對 `yes`／`no` logits 計分，再產生連續風險分數。
- 作者把 45.2M 公開文字樣本、4.4M 合成對比文字與 4.5M 多模態樣本統一成約 54.1M 筆訓練資料；作者報告 text safety 平均 F1 84.9%、multimodal safety 83.8%、細粒度 policy-adaptive evaluation 91.3%。
- **判讀：**價值在於「部署方用自然語言描述政策」，而不是被固定 taxonomy 綁死。所有數字仍是作者自建訓練／評測流程的結果，且部分資料與 evaluation 由 LLM 生成和交叉驗證；截至查核時未找到公開 checkpoint 或 API，不能把論文當成已可部署產品。
- 來源：[Shieldstral 論文](https://arxiv.org/abs/2607.25857)、[完整 HTML](https://arxiv.org/html/2607.25857)

### 4) 兩篇新研究指出 coding agent 與長期記憶的瓶頸其實都在「取對 context」

- **論文日期：CodeNib 2026-07-28；InMind 2026-07-27**
- CodeNib 為每個 repository commit 建立 lexical、dense、structural 多視角索引，再用單一 runtime 提供搜尋、symbol navigation 與 bounded context。作者在五個模型上報告，相較 paired grep／read 可少用 50%～87% trajectory tokens；graph／vector 增量更新的中位數速度分別是重建的 8.7×／25.4×。
- InMind 測試「文字不相似、但需靠常識連起來」的記憶，例如樹堅果過敏應影響馬卡龍建議。決定性記憶直接放入 context 時 backbone 可答對 84.0%；交給六種 vector、graph、agentic memory 系統自行取回時最高僅 14.4%，即使直接問該事實時 recall 可達 100%。
- **判讀：**一個問題是 repository context 被反覆重找；另一個問題是 retriever 根本不知道哪段記憶與問題有隱性關聯。兩者都顯示「更大的 context window」不能取代 context lifecycle、routing 與 abstention 設計。
- 來源：[CodeNib](https://arxiv.org/abs/2607.25431)、[InMind](https://arxiv.org/abs/2607.24368)

## 3. 新技術、新方法

### 方法一：Repository context 應有可失效、可增量更新的多視角索引

- **論文日期：2026-07-28；預印本**
- CodeNib 不把 grep、embedding、symbol graph 與 agent history 當成互不相干的工具，而是綁定 commit，明確定義每一種 view 在 edit 後何時仍有效。
- 實務上可先做最小版：lexical search 找候選、symbol graph 補相依、dense retrieval 處理自然語言，再把結果正規化成 repository-relative source ranges；每次修改後只更新受影響的 view。
- 作者結果來自 100 個 snapshots 與特定 navigation workload，不能直接外推成所有 repository 都會節省 50%～87% tokens。
- 來源：[arXiv:2607.25431](https://arxiv.org/abs/2607.25431)

### 方法二：記憶檢索要能推導關聯，而不只是比 embedding 相似度

- **論文日期：2026-07-27；預印本**
- InMind 把失敗拆成三類：記憶根本沒存、模型不知道中間知識、記憶有存但未被取出。它的 paired controls 顯示主要缺口落在 query-conditioned retrieval interface。
- **可用結論：**高風險偏好、過敏、法規身分或安全限制，不宜完全依賴「等 query 相似時再抓」。可以把少量不可忽略條件放進 always-visible profile，或先讓小型 router 用世界知識推導可能相關的記憶類別，再做窄檢索。
- **限制：**benchmark 只有 125 題，偏健康、wellness 與 safety；GPT-5-mini 同時擔任 answerer 與 judge，且 always-visible profile 會擴大隱私暴露，論文本身也不建議直接把所有記憶常駐 context。
- 來源：[arXiv:2607.24368](https://arxiv.org/abs/2607.24368)

### 方法三：學生推理走偏時，只讓 teacher 短暫接棒

- **論文日期：2026-07-28；預印本**
- Relay On-Policy Distillation 針對 prefix failure：student 一旦早期走錯，後續錯誤軌跡既浪費 compute，也讓 teacher supervision 失真。
- 方法在偵測到 teacher／student continuation 分歧時，讓 teacher 短暫產生一段修正軌跡，再交回 student。作者以 Qwen3-4B-Instruct-2507 teacher 與 0.6B／1.7B students 測八個數學 benchmark，報告 1.7B 相對標準 OPD 平均 +5.73%，訓練軌跡長度減少超過 50%。
- **可用結論：**昂貴 teacher 不必接管整條 trajectory；把 intervention budget 集中在早期轉折點可能更有效。數字仍是作者結果，且目前證據集中在數學推理，不等於 coding／tool-use agent 也會有同樣收益。
- 來源：[arXiv:2607.26057](https://arxiv.org/abs/2607.26057)、[專案程式碼](https://github.com/zju-real/Relay-OPD)

### Copilot review skills：先測「有沒有真的被用到」，再談品質提升

- **社群／實務觀察日期：2026-07-29**
- GA 新增的 attribution 很重要，因為它能分辨 comment 只是通用模型意見，還是真的用到 skill 或 MCP context。

## 6. 今天值得嘗試

### 60 分鐘實驗：把 code review skill 變成可量測的控制項

挑一個沒有機密的測試 repository：

1. 在 `.github/skills/review-policy/SKILL.md` 寫 3 條可機器驗收的規則，不超過一頁。
2. 建立 6 個小 PR：3 個刻意違規、3 個正常對照。
3. 讓 Copilot code review 執行，記錄 comment 是否有 skill／MCP attribution。
4. 對每個 PR 計算 rule recall、false-positive rate、引用證據正確率與建議可執行率。
5. 若接 MCP，只提供 read-only、非敏感測試資料，另外放一段惡意指令測 prompt injection resistance。
6. 只有在指標優於「沒有 skill」的 baseline 時，才把規則推廣到正式 repository。

成功標準不是產生更多 review comments，而是抓到已知違規、少打擾正常 PR，而且每一條意見都能追溯到正確規則與證據。
