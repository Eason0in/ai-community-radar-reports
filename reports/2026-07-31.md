### 3) Copilot for Word 被示範可讓惡意指令沿著文件工作流自我傳播

- **披露日期：2026-07-28；2026-07-30 更新**
- 研究者 Håkon Måløy 在與 Microsoft Security Response Center 協調 144 天後，公開 document-borne AI worm PoC：外部 Word 文件中的白字隱藏指令可影響 Copilot 草稿、竄改數字，並把指令複製進新文件；新文件再被拿來當來源時，原始惡意檔不在場仍可繼續傳播。
- 研究者公布的時間線稱 Microsoft 已確認行為並上線兩輪緩解，但修改 payload 後仍可重現整類攻擊；截至披露時沒有完整的客戶端修補。這是**協調披露的研究者 PoC**，不是 Microsoft CVE 公告，實際成功率與不同租戶設定仍待更多驗證。
- **立即防護：**把外部文件當不可信資料；不讓 agent 自動搜尋 OneDrive 後直接產出高風險文件；對 AI 改寫保留來源與 edit provenance；財務、合約與政策文件在分享前做數值 diff、隱藏文字掃描與人工覆核。
- 來源：[完整技術披露](https://enklypesalt.com/posts/context-collapse-part3-ai-worming-through-word/)、[Hacker News 討論](https://news.ycombinator.com/item?id=49096188)

### 5) 六天、數千美元算力仍做不出可接受研究：open-ended AI research 的新型 shadow evaluation

- **論文日期：2026-07-29；預印本**

## 3. 新技術、新方法

### 長政策文件不能取代可執行 guardrails

- **論文日期：2026-07-28；COLM 2026 Workshop 論文**
- HANDBOOK.md 用 65 個長週期 agent 任務、20～124 頁 SOP、五個產業與 824 條程式化 criteria，測試 agent 是否真的受 standing policy 約束。
- 30 種 model configuration 中最佳 strict pass rate 只有 36.2%，多數 frontier configurations 低於 25%。常見失敗包括：讓環境內看似合理的要求蓋過政策、完成檢查後反而違反檢查結果、長途執行遺失規則細節，以及宣稱遵循但實際未做到。
- **可用方法：**把「不得做什麼」落成 tool permission、schema validator、dry-run、transaction boundary 與 post-condition test；文字規則負責意圖，可執行控制負責阻止錯誤。
- 來源：[arXiv:2607.25398](https://arxiv.org/abs/2607.25398)、[公開 benchmark](https://github.com/surge-ai/handbook)

### 多 Agent 的 latent message 要做替換實驗，不能只看最終分數

- **論文日期：2026-07-29；預印本**
- 一篇 causal audit 對 sender 傳給 receiver 的連續 latent representation 做四種 controlled replacement，拆分「有 message」「message identity」「本題特定內容」與「另一個 agent 的額外價值」。
- 在 Qwen3-4B／8B、GSM8K、ARC-C、MATH-500 上，總 accuracy gain 可能掩蓋方向相反的成分；例如 GSM8K 的 4B 總效果為 -1 point，實際由 other-example message 的 -6.17 與 example-specific content 的 +5.17 抵消而成。
- **可用方法：**測 multi-agent communication 時加入空 message、其他題 message、self-substitution 與真實 sender message 四組；若只報 end-task accuracy，無法知道 receiver 是否真的使用了正確資訊。
- 來源：[arXiv:2607.26773](https://arxiv.org/abs/2607.26773)

### Agent Manager 把「多開幾個 terminal」變成狀態與 diff review 問題

- **v0.12.0 發布日期：2026-07-30；早期開源專案**

- PostHog 同期提出一個互補判準：工作「容易驗證、但難復原」時可以委派生成，最後動作仍要 gate；只有容易驗證且便宜復原的 dependency bump、lint、補測試，才較接近 self-driving。

### Word worm 與 HANDBOOK.md 指向同一件事：context 內的文字不是安全邊界

- **社群討論日期：2026-07-29～2026-07-30**
- 兩項內容分別在 Hacker News 引發數百則討論。最實用的共同結論不是「再寫更長 system prompt」，而是把資料來源、權限與可執行動作分層。
- 外部文件、issue、網頁、MCP output 應標成 untrusted data；模型可引用它們，但不得因此自行提升權限。高風險 action 要靠獨立 validator、approval 或 transaction policy 才能發生。

**建議學習／實作工作流程**

1. 先做單一 agent，讓 tool schema、錯誤與輸出可測。

5. 只有需要外部知識時才走 RAG；涉及購買、寫入、刪除或部署時插入 HITL／policy gate。

## 6. 今天值得嘗試

### 45 分鐘測試：把「外部內容」與「可執行指令」分開

在沒有機密的 sandbox 建立一個 agent：

1. 準備一份正常 SOP 與一份含隱藏惡意指令的測試文件。
2. 只開放 `read_document` 與 dry-run `draft_change`，不給正式寫入權。
3. 規定文件內容只能成為 evidence，不能改變 system policy 或 tool permission。
4. 加一個 deterministic validator：若 output 含未引用數字、隱藏文字或來源外指令就失敗。
5. 再加一個需要明確 diff 的 approval gate，才允許把草稿寫入測試目錄。
6. 保存完整 trace，記錄 agent 是否引用惡意文字、是否嘗試越權，以及 validator 是否抓到。

成功標準不是「模型說它忽略了 prompt injection」，而是惡意內容無法跨越獨立的權限、validator 與 transaction boundary。
