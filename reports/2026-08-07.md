### 2) ContextWeave：Agent 記憶評測開始量「工作完成」與「偏好符合」，不只測回憶正確率

- **發布日期：2026-08-05（arXiv），2026-08-06 列入近期更新。** ContextWeave 將 14 位參與者、跨數月且經隱私處理的工作軌跡重建為 1,005 個可執行任務，其中 568 個用於核心評測，並提供容器化環境、軌跡與任務級 rubric。[論文](https://arxiv.org/abs/2608.04830)
- 在固定模型的作者實驗中，最佳記憶設定把 Workspace Score 從 **68.08 提升至 78.20**，Preference Score 從 **41.50 提升至 70.60**；五個基礎模型在固定記憶元件下都有收益，但幅度不同。
- 最有價值的訊號是：帶有操作脈絡的「經驗型記憶」通常比短摘要更有用，卻也更容易被錯誤或誤導性回憶拖累。因此記憶系統不能只測召回率，還要測下游任務、偏好符合與 misleading recall。
- **限制：**這是作者自行提出的 benchmark，原始使用者樣本僅 14 人，且工作流經重建；不能直接外推成所有長期 Agent 的生產效益。

### 3) Canary Tools：用假的 MCP 工具選項，在造成真實副作用前暴露 Agent 判斷弱點

- **發布日期：2026-08-05（arXiv），2026-08-06 列入近期更新。** Canary Tools 在工具清單加入診斷用「金絲雀」，分成語意誘餌、參數陷阱、能力幻象、前置條件忽略、時間誘餌與粒度陷阱六類。[論文](https://arxiv.org/abs/2608.04719)
- 作者對 8 個模型執行 8,640 次主實驗，另做 2,880 次 subtlety ablation；不同模型的中招率相差約 36 倍。研究也顯示同一供應商內，較便宜的模型不必然比較不安全。
- Canary Selection Rate 與任務失敗呈負相關（作者報告 Spearman ρ = -0.34），因此它適合當作部署前的能力探針，而不是等付款、刪除或發信後才從事故學習。
- **限制：**這是合成診斷任務與 judge-based 評分，不能當成真實世界事故率；但很適合轉成團隊自己的 staging gate。

### 4) OctoLong：長上下文程式模型的訓練資料，應包含跨 repository 的真實依賴鏈

- **發布日期：2026-08-05（arXiv），2026-08-06 列入近期更新。** OctoLong 用 AST parser、language server 與套件管理器遞迴追蹤跨 repository 參照，建立包含依賴關係的百萬 tokens 程式上下文。[論文](https://arxiv.org/abs/2608.05141)
- 作者在 600M–14B 模型系列中，把約 6.2B OctoLong tokens 納入約 50B tokens 的 mid-training mixture，再進行約 10B tokens 指令微調；作者結果顯示，只替換傳統延伸語料的 12%，即可改善長距檢索、狀態追蹤、repository 理解與 agentic 任務。
- 實務含義不是「把 context window 開大」就夠，而是檢索與訓練資料要保留 symbol、套件與版本之間可執行的依賴結構。
- **限制：**摘要未提供各任務的完整提升數字；結果尚待獨立重現，實務上也要處理 LSP 覆蓋率、套件解析成本與跨 repository 授權。

## 3. 新技術、新方法

### 把記憶系統改成三層驗證

綜合 ContextWeave 的結果，一個比較實用的評測可以同時記錄：

1. **記得什麼：**事實與偏好是否召回正確。
2. **做成什麼：**工作區最終狀態是否通過任務 rubric，而不只看回答文字。
3. **錯了會怎樣：**植入一則過期或誤導記憶，觀察 Agent 是否交叉查證、降低信心或錯誤執行。

### 在 MCP／工具註冊表放低副作用 canary

Canary Tools 的做法可直接轉成 staging 測試：放入名稱相近但用途不同的工具、缺少必要權限的「能力幻象」，以及需要先讀取狀態才能呼叫的工具；只記錄選擇，不執行外部副作用。這比只測「模型會不會呼叫工具」更接近實際風險。

### 跨 repository context 要保留依賴，而非純文字拼接

OctoLong 提醒 RAG 與 coding agent 團隊：檢索時應把 symbol definition、call site、套件版本、generated client 與測試一起打包。單純依檔名或向量相似度塞滿長上下文，可能仍缺少真正決定行為的依賴鏈。

1. 用 Browser 做低風險、多來源研究，輸出附來源的結構化表格。

4. 排程任務先手動跑過一次；會改程式碼時放入 worktree，敏感／不可逆操作保留人工確認。
