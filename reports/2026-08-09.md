## 1. 今日最重要的 4 件事

### 1. RAG 的問題不只是假資料，而是模型「何時該信上下文」｜2026-08-06

新研究提出 **MIST**，用同一道題的乾淨、誤導、正確脈絡與無關脈絡四個版本，測量模型是否會被外部文字帶偏。作者測試 23 個模型，誤導脈絡平均造成 **17.1 個百分點**的正確率損失；即使原本答對，GPT-5.5、Gemini 3.1 Pro、Claude Opus 4.8 仍分別有 10.5%、12.9%、12.0% 被翻成錯誤答案。這是作者基準結果，不等同真實產品環境的失敗率。

作者同時提出 **SCOPE** 訓練法：不要只教模型忽略錯誤脈絡，也要保留它利用正確脈絡的能力。Qwen3-4B 的 SC2W（原本答對、加入誤導訊號後改錯）由 35.0% 降至 16.3%。對 RAG 團隊最實用的提醒是：評測集要同時測「拒絕誤導」與「採納正確證據」，不能只看答案是否忠於檢索內容。[論文與資料說明](https://arxiv.org/abs/2608.06377)

### 2. 影片模型可能答對次數，卻沒有看對事件｜2026-08-06

**The Low-Frequency Trap** 建立 2,190 支可精確追蹤事件的控制影片，測試反彈碰牆、短暫閃爍與狀態切換。高事件數、高頻率條件下，模型只有 **0.2%** 的最終計數完全正確，平均只找回 18.1% 的真實事件。更重要的是，提高取樣率讓反彈球任務正確率由 19.6% 升至 29.3%，但模型回報的事件序列只有 3.7% 真正吻合軌跡。

因此，多模態評測不能只核對最後答案；還要保存時間點、幀證據與事件序列，否則可能把「猜中」當成可靠理解。這仍是控制場景下的作者結果，尚不能直接外推到所有真實影片。[論文與基準](https://arxiv.org/abs/2608.06361)

### 3. Agent 評測可在證據足夠時安全停止，但捷徑有適用邊界｜2026-08-06

**AV-AIVAT** 對 15 組 LLM poker agent、71,439 組配對牌局加入 AIVAT 變異縮減，再以 anytime-valid confidence sequence 監測結果。作者報告中位數變異降低 54 倍；在名目 95% 信賴與 ±1 BB 目標下，原始結果相較於 AIVAT 加漸近式信賴序列，需要的手數中位數多 74 倍。

價值不在 poker 本身，而是評測可改成「邊跑、邊判斷證據是否足夠」，避免固定燒完整預算。不過 74 倍是特定遊戲、特定校正器與漸近設定的結果；論文中的有限樣本界線改善只有 1.37 倍，不能把 74 倍當成一般 Agent 評測保證。[論文](https://arxiv.org/abs/2608.06362)

### 4. MCP 新規格的真正風險開始浮現：相容性，不只是升級 SDK｜2026-08-08

7 月 28 日的 MCP 規格把協定層改為無狀態、移除初始化握手與 session ID，並加入 `server/discover`、MRTR、快取提示和路由標頭。8 月 8 日的 Rust SDK 回報顯示，第一個請求若缺少必要 `_meta`，stdio server 可能完全不回錯誤而卡住；另一個尚未合併的修正指出，舊伺服器可能用 `-32600`、`-32602` 或中介層錯誤拒絕 `server/discover`，不能只在 `-32601` 時回退。

這些是仍在處理的開放 issue／PR，不代表所有 MCP SDK 都有相同問題；但它們說明 migration checklist 必須包含錯誤分類、timeout、舊版 fallback 與 malformed-request 測試。[MCP 2026-07-28 發布說明](https://blog.modelcontextprotocol.io/posts/2026-07-28/)｜[Rust SDK issue #1157](https://github.com/modelcontextprotocol/rust-sdk/issues/1157)｜[Rust SDK PR #1133](https://github.com/modelcontextprotocol/rust-sdk/pull/1133)

## 3. 新技術、新方法

### A. 用四種脈絡測「選擇性信任」｜2026-08-06

為同一批題目建立四個版本：無脈絡、正確脈絡、誤導脈絡、無關脈絡。除了總正確率，再記錄 clean-to-wrong flip rate。這比單純測 RAG faithfulness 更接近實務：模型必須能利用好證據，也能拒絕壞證據。

### B. 多模態評測採 trace-first，而非 answer-only｜2026-08-06

要求模型輸出事件時間點、對應幀、事件種類與最終彙總；自動檢查完整事件序列，再評最終答案。若只提高 FPS 後分數變好，仍要確認證據軌跡是否同步改善。

### C. 用 anytime-valid 統計管理 Agent 評測預算｜2026-08-06

每新增一批任務就更新信賴區間；區間窄到足以支持決策才停止。若使用控制變量或遊戲專屬校正器，需另外驗證其假設與有限樣本界線，不能只報漸近效率。

## 4. 社群實戰心得

### MCP migration 最少要有四組反例測試｜2026-08-08

依 Rust SDK 的實作回報，可把相容性測試整理成：

1. 第一個請求缺 `_meta` 時，server 應回結構化錯誤而非靜默卡住。
2. `server/discover` 收到 `-32601`、`-32600`、`-32602` 或 HTTP／middleware 錯誤時，確認是否該回退舊握手。
3. 對「完全不回 discover」的舊 server 設定明確 timeout。
4. round-robin 部署下，顯式 state handle 必須能在任一實例恢復狀態。

這是從開放 issue／PR 推導的測試建議，不是 MCP 官方合規測試套件。

## 6. 今天值得嘗試

### 做一個 45 分鐘的「模型路由＋選擇性信任」回歸測試

1. 選一個現有 coding 或 RAG 任務，拆成研究、規格、執行、審查、修正五步。
2. 為每步標記模糊度、風險、輸出量與可驗證性，先指定便宜模型；只對高模糊／高風險步驟設定升級條件。
3. 對同一題各加入正確、誤導與無關脈絡，記錄 clean-to-wrong flip，而不只看最終總分。
4. 審查階段要求附檔案、行號、時間點或來源，讓強模型／人類能核對證據。
5. 同時記錄 token 成本、延遲、任務成功率與錯誤類型；至少跑 10 組再決定 routing 是否真的省錢。
